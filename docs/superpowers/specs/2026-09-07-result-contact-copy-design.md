# 报价结果页业务联系方式设计

## 目标

在报价结果页直接提供业务人员的微信联系方式，减少用户完成报价后的咨询阻力。MVP 使用演示手机号，后续可替换为员工或渠道配置，不接入数据库、留资或微信开放能力。

## 已确认方案

采用“联系方式直接展示 + 复制号码按钮”，不使用弹窗，也不提供拨号按钮。

结果页底部联系卡展示：

- 标题：`咨询业务人员`
- 演示号码：`138 0000 0000`
- 辅助标签：`微信同号`
- 主操作：`复制号码`

联系方式保持直接可见，按钮只负责降低复制成本。相比纯文字，按钮提供清晰行动入口；相比弹窗，不会隐藏关键信息或增加一次操作。

## 交互与反馈

点击“复制号码”后复制不含空格的 `13800000000`。

- 成功：按钮显示`已复制`，旁边或下方通过礼貌型状态区域提示`号码已复制，可打开微信添加`。
- 失败：号码仍保持可见，并提示`复制失败，请长按号码复制`。
- 不自动打开微信，不假设浏览器可以可靠唤起微信。
- 按钮使用原生 `button`，移动端触控高度不低于 44px，保留键盘焦点样式。

为兼容局域网 HTTP 预览，在现代 Clipboard API 不可用时提供浏览器内文本选择复制回退；静态导出部署在 HTTPS 后优先使用 Clipboard API。

## 代码边界

- 联系配置放在 `src/config/site.ts`，显示号码与可复制号码由同一配置派生，避免散落硬编码。
- 联系展示与复制逻辑放入独立的 `sales-contact-action.tsx`，延续现有 MVP 设计中的销售联系扩展边界。
- `result-step.tsx` 只组合结果内容和联系组件，不承载剪贴板细节。
- 不修改报价计算、规则版本、表单数据或 Pencil 设计稿。

## 验收

- 正常报价、部分人工报价、人工报价和不符合承保条件的结果页都能看到联系方式。
- 页面显示`138 0000 0000`和`微信同号`。
- 点击按钮复制`13800000000`，并出现成功反馈。
- Clipboard API 失败时显示可恢复提示，号码仍可长按选择。
- 360px 及 iPhone 17 Pro / Pro Max 宽度下无横向溢出，按钮触控高度达标。
