# 移动端报价流程信息层级优化设计

## 1. 背景与目标

当前报价流程已经具备移动端布局与动态步骤能力，但仍存在以下体验问题：

- 动态步骤数量直接参与当前进度计算，导致用户勾选险种后进度从 50% 倒退至 25% 或 20%。
- 顶部品牌、步骤、页面标题和进度标签重复占用首屏空间。
- 多个页面在标题、引导文案、卡片标题和底部提示中反复说明相同内容。
- 面积系数没有明确展示，且辅助说明与输入框缺少必要间距。
- 员工人数准入状态缺少符合语义的颜色和图标反馈。
- 底栏必须等所有险种配置完成后才显示金额，无法形成逐步累加的报价反馈。

本轮优化以移动端优先，目标是让用户在每一步都能快速理解当前位置、当前决策以及已经产生的保费，同时不改变保费规则、静态导出能力和最终报价校验。

## 2. 设计原则

1. 进度表达已经完成的流程，不表达当前字段填写比例。
2. 页面控件能够直接表达的操作，不再额外使用说明文字重复解释。
3. 承保边界、面积系数和许可证要求属于关键决策信息，必须保留并放在相关控件附近。
4. 状态不能只依靠颜色表达，必须同时使用图标和明确文案。
5. 底栏金额采用渐进式预览，但最终报价仍只在所有必填条件完整后生成。
6. 少于 8 人时遵循业务规则，不输出雇主责任险保费。

## 3. 顶部结构与进度逻辑

### 3.1 顶部信息层级

删除左上角的盾牌图标和“餐饮安心保”。每一步顶部只保留一行：

- 左侧：当前页面标题。
- 右侧：`第 N / M 步`。

页面标题统一为：

| 页面 | 标题 |
| --- | --- |
| 门店与险种 | 保费智能预估 |
| 雇主责任险档位 | 选择雇主险档位 |
| 员工人数 | 填写员工人数 |
| 公众险与食责险方案 | 选择保障方案 |
| 结果 | 报价结果 |

结果页可以保留步骤提示，使流程最终状态与前序页面保持一致。

### 3.2 进度语义

进度条表示“已完成步骤占比”，计算方式为：

```text
进度 = 已完成步骤数 ÷ 需要完成的步骤数
     = (当前步骤序号 - 1) ÷ (总步骤数 - 1)
```

因此：

- 首屏始终为 0%，不会因勾选不同险种改变。
- 进入下一页后才增加进度。
- 结果页固定为 100%。
- 动态跳过未选择险种对应的步骤时，进度按实际流程重新计算。

界面不显示百分比数字，也不再显示“门店与险种”“雇主险档位”等重复标签，只保留细进度条。进度条继续提供 `progressbar` 语义、`aria-valuenow` 和完整的 `aria-valuetext`。

## 4. 页面文案与内容调整

### 4.1 门店与险种页

删除标题下的通用介绍，不再重复说明填写门店信息和获得预估保费。

“门店信息”卡片保留经营面积输入，删除单独的“必填”徽标。经营面积标签本身保留清晰的必填语义和错误提示。

面积说明改成独立的动态规则框，并与输入框或错误提示保持 12px 上间距。不在移动端常驻展示完整面积档位表，只反馈当前输入对应的规则结果：

```text
未输入：输入经营面积后显示适用系数
输入 260㎡：当前系数：公众险 ×1.8，食责险 ×1.5
输入 2,500㎡：当前系数：公众险 ×3.5；食责险需人工报价
```

动态结果直接读取结构化规则中的面积档位，不在组件中复制或硬编码系数。无效面积继续由字段错误处理，不显示误导性的系数结果。

险种卡继续保留保障对象说明和起始价格。雇主责任险的“8 人起保”必须保留。

### 4.2 雇主责任险档位页

标题使用“选择雇主险档位”，标题下只保留一条与决策相关的说明：

```text
选择每位员工的保障额度。
```

保留每档的伤亡和医疗赔付上限。删除以下重复信息：

- “雇主责任险独立选择、独立计算。”
- “保费在下一步按岗位人数计算。”
- 页面底部的计算公式和“下一步自动计算”提示。

### 4.3 员工人数页

删除标题下的操作说明、卡片右侧的年龄文字以及年龄范围确认按钮。

MVP 默认所有员工符合年龄要求，`allEmployeesAgeEligible` 在前端报价输入中默认设为 `true`。字段和计算分支保留扩展能力，未来接入员工明细时仍可根据实际年龄写入异常状态。本轮不修改业务规则 Markdown 或 JSON。

员工人数卡片下方保留一条中性提示：

```text
投保员工须为 16–65 周岁，正式投保时核验。
```

人数准入状态分为：

- 少于 8 人：浅红背景、红色感叹号，并显示“共 N 人，还差 X 人达到 8 人起保要求”。
- 达到 8 人：浅绿色或中性背景、绿色勾选，并显示“共 N 人，满足最低承保人数”。

少于 8 人时不输出保费，符合现有“不承保、不转人工报价、不输出保费”的规则。

### 4.4 公众险与食责险方案页

删除标题下“分别选择一档保障方案”的说明。方案卡本身已经表达操作。

保留各方案的限额与基础价格。删除公众责任险“按门店计费”以及页面底部“按面积系数、按一年展示”的重复说明。

食品安全责任险保留资料提示，并统一使用“食品生产许可证”。许可证不作为 MVP 报价输入，只在正式投保资料中核验。

### 4.5 结果页

- 非正常报价状态只保留一个主标题，不在眉题和标题中重复状态名称。
- 部分人工报价合并为一条完整状态说明：已知保费小计、待确认项目数量以及暂不展示最终总价的原因。
- “保障与免赔要点”只显示已选险种对应的内容。
- 尚未接入联系方式时，不显示可点击但没有行为的销售按钮；保留非交互的销售支持扩展区域。
- 正式投保资料统一使用“食品生产许可证”。

## 5. 底栏渐进报价

最终 `calculateQuote` 的完整校验和状态语义保持不变。新增独立的纯 TypeScript 预览计算模块，只计算当前已经具备输入条件的项目。

### 5.1 状态规则

| 当前阶段 | 底栏第一行 | 底栏第二行 |
| --- | --- | --- |
| 门店与险种 | 已选 N 个险种 | 继续选择保障方案 |
| 雇主档位未选 | 雇主责任险 | 请选择保障档位 |
| 雇主人数少于 8 人 | 雇主责任险 | 还差 X 人达到起保要求 |
| 雇主人数达到 8 人 | 雇主险当前预估 | `¥X / 年` |
| 公众险或食责险已选部分方案 | 当前已选保费 | 已完成项目的累计金额 |
| 所有项目可自动计算 | 预估合计 | 所有险种累计金额 |
| 同时存在人工报价项目 | 已知保费小计 | `¥X + N 项待确认` |
| 已有项目但均需人工报价 | 当前报价 | `N 项需人工确认` |

### 5.2 计算边界

- 雇主责任险只有在档位已选、人数均为非负整数且总人数达到 8 人时才计入预览。
- 公众责任险和食品安全责任险在面积有效且对应方案已选后计入预览。
- 超过面积自动报价范围的项目不计入金额，并计入“待确认项目”。
- 预览金额只能用于界面即时反馈，不能作为最终提交结果。
- 最终结果仍由完整输入和规则版本重新计算。

## 6. 组件与数据边界

1. `ProgressHeader` 只负责顶部标题、步骤提示和完成度进度条，不感知险种业务。
2. 报价向导根据动态步骤数组提供当前序号和总步骤数。
3. 新增预览计算纯函数，输入为当前报价草稿与规则，输出已知小计、已完成项目数、人工确认项目数及雇主险准入状态。
4. `BottomBar` 只渲染预览摘要，不自行计算金额。
5. 各步骤组件只展示与当前决策直接相关的说明和状态。

## 7. 可访问性与移动端约束

- 顶部标题保持正确的 `h1` 层级。
- 进度条保留可访问名称、当前值和文本说明。
- 错误提示继续与对应输入通过 `aria-describedby` 关联。
- 红色警告同时使用感叹号图标和明确文案，绿色成功状态同时使用勾选图标和文案。
- 所有输入和按钮触控区域继续保持至少 44px。
- 底栏继续避开安全区，并在软键盘打开时收起。
- 金额使用等宽数字特性，避免输入人数时底栏发生明显跳动。

## 8. 测试与验收

### 8.1 单元测试

- 首屏动态选择任意险种时，完成度保持 0%。
- 结果页完成度为 100%。
- 雇主险人数少于 8 人时，预览不返回金额。
- 雇主险人数达到 8 人时，立即返回该险种金额。
- 公众险和食责险方案逐个选中时，已知小计逐步累加。
- 存在超面积项目时，保留可计算项目小计并返回待确认数量。
- 没有年龄输入时按默认合规完成 MVP 报价。

### 8.2 端到端测试

- 首页不再显示“餐饮安心保”，标题和步骤提示位于同一行。
- 勾选一个或多个险种时进度不倒退。
- 面积输入后显示当前适用系数或人工报价状态，并与输入框存在清晰间距。
- 雇主险档位页不存在重复的按人数计算说明。
- 员工页不存在年龄确认按钮，仍显示年龄核验提示。
- 少于 8 人显示红色警告图标，达到 8 人显示绿色成功图标。
- 达到 8 人后底栏显示雇主险即时金额。
- 后续方案选择时底栏金额按已完成项目逐步累加。
- 结果页只显示已选险种相关的保障与免赔内容。

### 8.3 回归验证

- 运行 ESLint、TypeScript 类型检查、全部单元测试和静态导出构建。
- 在 Chromium 移动端、iPhone 17 Pro 和 iPhone 17 Pro Max 配置下运行全部 Playwright 测试。
- 检查 360px 窄屏和横屏无横向溢出。
